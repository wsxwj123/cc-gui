## #1 文件树 ⋮ 菜单(真机 bug 修复)

### 正例
1. **[真机硬门]** 打包 app 里打开文件树,任一普通文件行点 ⋮ → 菜单弹出,出现在 ⋮ 按钮附近、完整在视口内,含"添加到上下文 / 用默认 App 打开 / 删除"三项。
2. **[真机硬门]** 菜单打开状态下点菜单外任意空白(遮罩)→ 菜单关闭,无残留浮层。
3. **[真机硬门]** 根目录行点 ⋮ → 菜单含"删除项目文件夹…";点它 → 进入危险确认弹层(与现状一致,可取消)。
4. **[真机硬门]** 点"用默认 App 打开" → 该文件由系统默认程序打开(等价现有 `POST /api/files/open` 行为)。

### 反例/边界(挑毛病)
5. **[真机硬门]** 树最右侧、最深嵌套那一行(缩进最多)点 ⋮ → 菜单**不飞出屏幕右界**、不被面板裁掉,三项都可点。
6. **[真机硬门]** 超长文件名(撑满行宽)那一行点 ⋮ → 菜单定位仍锚在 ⋮ 附近,不因文件名长度错位或溢出。
7. **[真机硬门]** 靠近视口底部的行点 ⋮ → 菜单不被底边裁掉(向上翻转或收进视口)。
8. **[真机硬门]** 连续对不同行点 ⋮ → 同一时刻只存在一个菜单,不叠加多个浮层。
9. **[手动/浏览器]** dev Chromium 里点 ⋮ 也能弹菜单(dev 本就"看着正常",不得因本次修复反而在 dev 弹不出=回归)。

### 回归风险点
10. **[真机硬门]** 删除/添加到上下文动作走完后,文件树本身仍正常(能展开折叠、能点开文件、批量多选模式入口不受影响)。
11. **[真机硬门]** 右键(若真机原生层仍吞掉)不作为判据;⋮ 左键入口是唯一验收路径——不得要求裁判去试右键。

## #2 思考折叠增强(摘要 + 流式动态状态)

### 正例
1. **[手动/浏览器]** 一条已完成的 AI 回复,其思考块折叠态标题显示**内容摘要形态**(如"已思考 · <思考首句>"),不再是固定"思考过程"。
2. **[手动/浏览器]** 点该折叠条展开 → 显示**完整**思考正文(不截断、不只显示摘要)。
3. **[手动/浏览器]** 发一条会触发工具调用的消息,流式进行中观察气泡底部:出现**一行随当前动作变化的状态文字**——读文件时含"正在读取"+文件名;思考时"正在思考…";执行命令时"正在运行"类文案;产出回复正文时"正在回复…"。
4. **[手动/浏览器]** 回复完成后 → 该状态行消失。

### 反例/边界(挑毛病)
5. **[手动/浏览器]** 思考正文为空或极短(几个字)的回复 → 折叠标题**回退显示"思考过程"**,不显示半截摘要、不报错、不空白崩溃。
6. **[手动/浏览器]** 历史(非流式)会话里的 turn → **不出现**底部动态状态行(状态行只属于进行中的流)。
7. **[手动/浏览器]** 快速连续多轮对话 → 上一轮的状态行不残留到下一轮;同一时刻不出现两条状态行。
8. **[手动/浏览器]** 思考首句含特殊字符/超长句 → 折叠标题摘要截断合理,不撑破布局、不注入 HTML。

### 回归风险点
9. **[手动/浏览器]** 普通历史消息(纯文本、代码块、含图片)展示不变——本项改 turn 渲染,不得破坏无思考块消息的正常显示。
10. **[手动/浏览器]** 长会话上下滚动 → 历史思考块仍可正常展开/折叠,无卡顿加剧或错位(此前有长会话渲染性能坑,别回退)。

## #3 停靠预览(冻结 bug 修 + 内联折叠)

### 正例
1. **[手动/浏览器]** AI **正在生成**一个可预览代码块(html/svg/mermaid),点"停靠" → 右侧停靠面板的**代码与预览随后续流式输出继续更新**,最终与完整代码一致,**不冻结**在点击瞬间的快照。
2. **[手动/浏览器]** 预览 iframe 在流式中约每 ~300ms 刷新一次(肉眼可见渐进更新,不是一次性跳到终态也不是卡住不动)。
3. **[手动/浏览器]** 点"停靠"后,对应**内联**代码块主体折叠为紧凑代码块,但**仍保留 预览 / 代码 / 停靠 三个工具栏按钮**可点。
4. **[手动/浏览器]** 生成结束后停靠面板内容 = 该代码块最终完整内容,预览渲染正确。

### 反例/边界(挑毛病)
5. **[手动/浏览器]** 从**文件浏览器**停靠(coexist 模式)的面板 → **保持不折叠**,行为与现状一致(内联折叠只作用于会话内代码块停靠,别误伤文件停靠)。
6. **[手动/浏览器]** 停靠一个块,流式中再生成第二个可预览块 → 停靠面板仍跟随被停靠的那个块更新,不串到新块。
7. **[手动/浏览器]** 停靠后**切换到另一个分屏窗格**再切回 → 停靠面板内容/折叠态不错乱、不冻结、不丢失(停靠面板是单例,per-pane 切换是历史高危区)。
8. **[手动/浏览器]** p5.js / three.js 代码块(本轮不做实时渲染)→ 现状可预览的仍可预览,不可预览的**不得因本次改动崩溃或白屏**(非可预览块正常显示为代码)。
9. **[手动/浏览器]** 停靠中途点"停止" → 面板停在已收到的内容,不报错、不无限"更新中"。

### 回归风险点
10. **[手动/浏览器]** 非可预览的普通代码块(如 python/bash)在会话内**正常显示为代码块**,不被误折叠、不误加预览按钮、不白屏(本项改渲染逻辑,最易误伤这里)。
11. **[手动/浏览器]** 已停靠面板的"代码/预览"切换、关闭停靠按钮均正常。

## #5 worktree 列表刷新

### 正例
1. **[手动/浏览器]** 打开 worktree 选择弹层 → 弹层内可见**刷新控件**。
2. **[手动/浏览器]** 弹层开着时,在别处(终端 `git worktree add` 或让 AI 新建)新增一个 worktree,再点刷新 → 列表**重新拉取**,新 worktree 出现在列表中。

### 回归风险点

## #6 settings.json 外部改动同步显示

### 正例
1. **[手动/浏览器]** 打开设置面板,终端执行 `cc switch`(或编辑器手改 `~/.claude/settings.json`)→ 面板显示在 **≤3s 内自动反映新值**,无需手点"重新加载"。
2. **[可自动化]** 改动 `~/.claude/settings.json` 后,前端收到既有 WS 转发的 `provider-change` 事件(载荷 `{ type:'provider-change', path, providerFp }`),名称与形态未变。可用 WS 客户端订阅观测,或 curl `GET /api/settings` 确认后端已读到新值。

### 反例/边界(挑毛病)
3. **[手动/浏览器]** 面板处于 **dirty(有未保存编辑,如正在改 settings JSON 草稿)** 时发生外部改动 → 自动刷新**不得静默吞掉**用户正在输入的内容(可以提示/合并/延后,但用户草稿丢失=不合格)。
4. **[手动/浏览器]** 设置面板**关闭**时的外部改动 → 不产生可见错误;下次打开面板显示的是最新值。
5. **[可自动化]** 频繁连续改 settings.json(2s 内多次)→ 后端 polling(2.5s 采样)天然去抖,不产生风暴式刷新;观测窗口 ≤3s 内最终收敛到最新值。
6. **[可自动化]** 该 WS 事件的其他既有消费者(ModelSelector / providerEpoch 逻辑)行为不变——切 provider 后模型解析仍正确,不因新增订阅而被干扰。

### 回归风险点
7. **[可自动化]** `GET /api/settings`、`PUT /api/settings`、`POST /api/settings-env` 请求/响应形态不变。
8. **[手动/浏览器]** 面板内手动"保存/切换"仍正常写入并生效(自动刷新不覆盖用户主动保存的动作)。

## #7 图片点击放大 lightbox(决策已定:单击放大、图片去双击、文件卡保持双击)

### 正例
1. **[手动/浏览器]** 输入框中已添加的图片附件,**单击** → 全屏 lightbox 放大;点背景或按 **Esc** → 关闭。
2. **[手动/浏览器]** 已发送消息中的图片附件,**单击** → lightbox 放大;lightbox 内提供"用默认 App 打开"入口,点它按系统默认程序打开该图。
3. **[手动/浏览器]** lightbox 图片按视口等比放大(约 92vw/92vh 上限),**不溢出、不撑破布局**,大图小图都居中显示完整。

### 反例/边界(挑毛病)
4. **[手动/浏览器]** 已发送消息中的**非图片文件**附件 → **仍保持双击打开默认 App**(单击不触发 lightbox,行为不变)。
5. **[手动/浏览器]** 图片附件**双击** → 不再触发"打开默认 App"(双击已按决策去除;单击已经放大,双击不应有额外副作用/不报错)。
6. **[手动/浏览器]** **连点/快速多次点击**同一图片 → 只弹一个 lightbox,不叠多层;关闭后能再次单击重新打开。
7. **[手动/浏览器]** lightbox 打开时按 Esc → 只关 lightbox,不误触发上层其它 Esc 行为(如中断会话/关面板);关闭后焦点回到正常状态。
8. **[手动/浏览器]** 超宽/超高/超小图片各一张 → 均在 92vw/92vh 约束内正确等比缩放,不拉伸变形、不溢出滚动条。
9. **[手动/浏览器]** 移动端/窄视口或分屏窄窗格中单击图片 → lightbox 仍在视口内正确显示、可关闭。

### 回归风险点
10. **[手动/浏览器]** 输入框中图片附件的**移除(×)**按钮仍可点、仍能删除附件(单击放大不得吞掉移除按钮的点击)。
11. **[手动/浏览器]** 已发送消息中的文件卡片(非图片)双击打开链路完好——本项动附件卡片渲染,最易误伤文件双击。
12. **[手动/浏览器]** 消息里图片与文本混排、多张图片时,点其中一张放大的是**被点的那张**,不串图。
