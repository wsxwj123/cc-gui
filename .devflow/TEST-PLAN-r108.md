## 明确没覆盖的（别当成"全绿=Windows 没问题"）

1. **真 Windows 机器上的真实行为**：本批全在 mac 上靠注入模拟。NTFS 大小写不敏感是否真的让 `existsSync` 够用、真机 `where`/PowerShell 的输出形态，都要真机 dogfood。
2. **性能类断言**：`--help` 探测从 5s 降到 2s、绝对路径提示 1.5s 内返回、"启动不被阻塞"——这些是时长/体感指标，测试里只验了"超时会给兜底""进程不被定时器挂住"，没测真实耗时。
3. **Defender / 杀毒扫描**：readdir 少跑到底省多少时间、exe 被隔离时的真实错误码，模拟不出来。
4. **INTERFACE §2 的启动挂点（server/index.js）**：需要起后端才能验，本批不起服务，没覆盖"listen 后确实去重预热了两条路径、异常被吞、只打一行日志"。
5. **INTERFACE §3.2 的 `resolveMcpCommandWin` 本体**：它会真去跑 `where`/PowerShell，mac 上无法黑盒验；只验了它依赖的缓存工厂 `makeTtlCache`。缓存 key 拼法（command + PATH）也没验。
6. **`spawnMcpCommand` 真正 spawn 的那一步**：只验了 `winCmdSpawnSpec` 算出来的启动参数，没验它确实被 spawn 用上（要真机或改造成可注入 spawn）。
7. **INTERFACE §5 的注释更新**：纯注释，无行为，不测。
