# INTERFACE — 对外可观测契约(测试设计唯一输入)

只写"用户/测试能观测到的行为契约",不写实现。本轮 7 项**几乎不新增后端接口**:#6 后端已存在,其余为纯前端可观测行为。

---

## 后端端点 / WS 事件

### 无新增端点
本轮不新增任何 HTTP 端点,不改任何现有端点的请求/响应形态。以下现有端点行为**保持不变**(向后兼容):
- `GET /api/settings`、`PUT /api/settings`、`POST /api/settings-env`(#6 复用)。
- `GET /api/worktree?cwd=<path>` → `{ trees: [...] }` 或 `{ error }`(#5 复用,不改)。
- `POST /api/files/open`(#7 lightbox 内"用默认 App 打开"复用)。
- `GET /api/files/list`、`POST /api/files/delete`(#1 菜单动作复用,不改)。

### WS 事件(#6)— 已存在,不新增、不改形态
- 事件:`{ type: 'provider-change', path, providerFp }`,在 `~/.claude/settings.json` 发生**任何**改动时由后端 file-watcher 广播(现状即如此)。
- 契约保证:本轮**不改**该事件的名称与载荷。前端 SettingsPanel 新增对既有 `cgui:provider-change` window 事件(由 WS 转发)的订阅来刷新显示——这是纯前端消费,不影响任何其他既有消费者(ModelSelector/providerEpoch 逻辑不变)。
- 去抖由后端 polling(2.5s 采样)天然提供;测试观测窗口按 ≤3s 计。

## 前端可观测行为判据(按项)

### #1 文件树 ⋮ 菜单
- 在**打包 app(WKWebView)**中,文件树任一行点 ⋮ → 上下文菜单出现在 ⋮ 按钮附近视口内(不飞出屏幕右界),含"添加到上下文 / 用默认 App 打开 / 删除"。
- 点菜单外遮罩 → 菜单关闭。
- 根目录行 ⋮ → 菜单含"删除项目文件夹…",点击进入危险确认(行为同现状)。
- 硬门:dev Chromium 不作为验收依据,必须真机验。

### #2 思考折叠
- AI 回复的思考块折叠态标题显示内容摘要形态(如"已思考 · <首句>"),而非固定"思考过程";思考正文空/极短时回退显示"思考过程"(不崩)。
- 展开后仍显示完整思考正文。
- 流式进行中:气泡底部出现一行随当前动作变化的状态文字——读文件时含"正在读取"+文件名、思考时"正在思考…"、执行命令时"正在运行"类文案、回复文本时"正在回复…"。
- 回复完成后该状态行消失;历史(非流式)turn 不出现状态行。

### #3 停靠预览
- 生成中的可预览代码块(html/svg/mermaid)点"停靠"后,右侧停靠面板的代码与预览**随后续流式输出继续更新**(预览 iframe 约 300ms 节流刷新),不冻结在点击瞬间的快照。
- 点"停靠"后,对应内联代码块主体折叠为紧凑代码块,但仍保留 预览 / 代码 / 停靠 三个工具栏按钮。
- 从文件浏览器停靠(coexist)的面板保持不折叠(行为不变)。

### #4 子代理会话过滤
- 若采用兜底版:含 `isSidechain:true` 标记(无论出现在 transcript 头或尾)的 jsonl 不出现在会话列表;所有正常(含 user 记录、无 sidechain 标记)的会话仍完整列出——**不得因本改动少显示任何真实会话**。
- 若不做:无可观测变化。

### #5 worktree 列表
- worktree 选择弹层内提供刷新控件;弹层开着时点刷新 → 列表重新拉取,新建的 worktree 出现。
- 不改 worktree 列表项的展示字段与"进入/新建"行为。

### #6 settings 同步
- 设置面板打开状态下,外部(终端 `cc switch` / 编辑器手改)修改 `~/.claude/settings.json` → 面板显示在约 ≤3s 内自动反映新值,无需手点"重新加载"。
- 边界契约:若面板有未保存的用户编辑(dirty),自动刷新不得静默丢弃用户正在输入的内容(具体策略实现时定,但"吞掉用户草稿"视为不合格)。

### #7 图片放大
- 输入框中已添加的图片附件,单击 → 全屏 lightbox 放大;点背景或按 Esc → 关闭。
- 已发送消息中的图片附件,单击 → lightbox;lightbox 内提供"用默认 App 打开"入口。
- 已发送消息中的**文件(非图片)**附件保持双击打开默认 App(行为不变)。
- lightbox 图片按视口等比放大(约 92vw/92vh 上限)不溢出、不撑破布局。
- 卡点1(已发送图片是"单击放大+移除双击" 还是 "单击放大+保留双击打开")由用户拍板;测试用例待该决策确定后据 PLAN 推荐/备选二选一编写。

## 向后兼容总约定
- 不删除、不重命名任何现有 HTTP 端点、WS 事件类型、window 自定义事件(`cgui:provider-change` / `cgui:sessions-changed` / `cgui:project-file-change` / `cgui:composer-fill` 等)。
- 现有会话列表、停靠面板单例、per-pane 门控、权限/provider 失效语义均不改动。
- 新增仅为:1 个前端组件(ImageLightbox)、1 个 store action(updateArtifactDockCode,新增不影响既有)、若干组件内监听与渲染增强。
