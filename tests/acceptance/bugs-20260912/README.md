```sh
cd tests/acceptance/bugs-20260912
./run-isolated.sh                    # 全量（13 条，约 2~3 分钟；T-401 一条就要 1 分钟左右）
```

## 已知边界

- T4 的目标形态已定并已落进断言：备份照留、砍掉应用内全文查看、入口改成「在访达中显示」。
  判据是"界面里有没有再出现超过 20 万 px 的块 / 超过 30 万字符的文本节点"+"点它界面最久多久没应答"，
  与按钮文案无关（文案只做形态断言）。
- 跑一次全量会在屏幕上弹出 2 个访达窗口（T-401 界面点击 + T-402 端点调用），这是该功能的真实行为。
- T4 的入口用的是同一族历史操作里的「官方兼容体检与清理」，不是用户原话里的"编辑消息重发"：
  后者要在 UI 里走编辑→重发，而重发需要真回合（隔离实例没有可用凭据）。裁剪那条路另由 T-403 取证。
- T1 的排队态钉在产品的暂停态上（「并入结果无法确认，已暂停后续队列」）：普通排队条目进会话
  1.5 秒内就会被自动发出（产品正常行为），测不稳；被量的长消息本身是普通排队条目形态。
- 生图那半只测**预览**：提示词清空实测不复现（localStorage 确实是空的），按口径不写用例。
